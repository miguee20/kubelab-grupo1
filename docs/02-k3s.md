# 02 · Instalación de Kubernetes (k3s)

## Por qué k3s (INF-04)

| Criterio | k3s | kubeadm | RKE2 |
|---|---|---|---|
| RAM del control plane | ~500 MB | ~1.5 GB (etcd, apiserver, controller y scheduler separados) | ~1.2 GB |
| Instalación | Un binario y un comando por nodo | Varios paquetes, runtime y CNI por separado | Similar a k3s, pero más pesado |
| Datastore | SQLite (kine), suficiente para 1 control plane | etcd | etcd |
| Certificación | Distribución certificada por la CNCF | — | Certificada |

Con 6 GB de RAM físicos y 4 VMs de ~1 GB cada una, k3s es la única opción que deja memoria libre para las aplicaciones, la observabilidad y Argo CD. Es Kubernetes estándar: usa los mismos objetos, kubectl y CRDs.

## Instalación

En la shell de `pve`:

```bash
curl -fsSL https://raw.githubusercontent.com/miguee20/kubelab-grupo1/main/scripts/proxmox/03-install-k3s.sh -o 03.sh && bash 03.sh
```

El script [`03-install-k3s.sh`](../scripts/proxmox/03-install-k3s.sh) instala el servidor en `k3s-cp` y une los 3 workers con el token del servidor. También instala `kubectl` en el host `pve`.

### Opciones relevantes

| Opción | Motivo |
|---|---|
| `--disable traefik,servicelb` | Traefik y MetalLB se instalan con Argo CD desde `k8s/platform` (NET-01, NET-02) |
| `--disable local-storage` | La StorageClass por defecto es NFS (PER-01) |
| `--disable metrics-server` | Se instala con Argo CD (HA-04), así queda versionado en el repo |
| `--node-taint node-role.kubernetes.io/control-plane=true:NoSchedule` | El control plane no ejecuta cargas de aplicaciones (INF-05) |
| `system-reserved` y `eviction-hard` | Reservan memoria para el sistema operativo y desalojan pods antes de que el nodo se quede sin RAM |

## Verificación

```bash
kubectl get nodes -o wide
```

Resultado esperado: 4 nodos `Ready`. `k3s-cp` aparece con el rol `control-plane` y el taint `NoSchedule`, y `k3s-w1..w3` con el rol `worker`.
